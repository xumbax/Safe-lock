# Хранение данных

## Что хранится

- **Код:** длина и символы.
- **Состояние:** режим (норма / блокировка / одна попытка) и счётчик ошибок.

## Как хранится

Каждая запись хранится в **трёх копиях** в разных местах EEPROM. Каждая копия состоит из таких полей:

| Поле | Размер | Зачем |
|---|---|---|
| метка | 1 байт | отличает «новый чип / чужие данные» от «испорченных данных». Пишется один раз и больше не меняется |
| номер записи | 4 байта | растёт с каждой записью, по нему выбирается самая свежая копия |
| данные | 9 / 2 байта | код / состояние |
| CRC16 | 2 байта | обнаруживает порчу данных (ошибка пропускается с вероятностью 1/65536) |

Раскладка EEPROM: копии кода по адресам 0, 128 и 256, копии состояния по адресам 384, 512 и 640.

**Запись.** Новый номер равен наибольшему номеру среди целых копий плюс 1. Копии записываются **по очереди**, каждая сразу проверяется чтением, при несовпадении запись повторяется. Запись считается успешной, если верно легли хотя бы 2 копии из 3.

**Чтение при включении.** Из целых копий (метка и CRC сходятся, данные допустимые) берётся копия с наибольшим номером, и остальные перезаписываются ею. Сама лучшая копия при этом никогда не перезаписывается.

## Почему обрыв питания ничего не ломает

В любой момент записи оборван может быть только **один** байт одной копии. Остальные копии либо уже новые, либо ещё старые, и все они целые. При включении выбирается свежайшая целая копия, поэтому результат **всегда либо старое значение, либо новое**. Мусора не бывает.

Для защиты от работы на просевшем питании нужен BOD (см. [фьюзы](firmware.md#фьюзы-bod)). Прошивка предупреждает, если он выключен. Кроме того, после включения она выжидает 300 мс до первой записи, чтобы не писать во время дребезга тумблера.

## Защита логики от обхода отключением питания

- Попытка ввода **сначала записывается как неудачная** (счётчик +1), и только потом код проверяется. Если выдернуть питание в момент проверки, попытка уже засчитана, а результат проверки злоумышленник так и не узнал.
- Если память не пишется (износ), код **не проверяется** и звучит сигнал неисправности. Отказ всегда в сторону «закрыто».
- Состояние блокировки хранится в памяти, поэтому после выключения питания блокировка начинается заново.
- Если испорчены все копии **состояния**, замок уходит в блокировку, а не в «норму».
- Если испорчены все копии **кода**, замок **не** сбрасывается сам на `0000`: это была бы дыра в защите. Он подаёт сигнал неисправности, а сбросить код можно только внутренней кнопкой, то есть после открытия механическим ключом.
- Код сравнивается целиком, без раннего выхода на первом несовпадающем символе.

## Ресурс EEPROM

Ресурс ячейки ATmega328P — 100 000 перезаписей, данные хранятся 20+ лет. При 2 открытиях в день за 5 лет одна ячейка перезаписывается около **7 300 раз**, то есть расходуется около 7 % ресурса. Библиотека EEPROM не перезаписывает байты, которые не изменились.

## Тест на ПК

Модуль хранения (блок между `STORAGE-BEGIN` и `STORAGE-END` в прошивке) проверяется тестом [`test/storage_test.cpp`](../test/storage_test.cpp) с имитацией EEPROM. Тест проверяет:

- **1035 сценариев обрыва питания** на каждом байте каждой записи, для 10 разных операций: ошибки, блокировка, смена кода, сброс. Оборванный байт имитируется пятью способами: старое значение, новое, `0xFF`, частично записанные биты, случайный мусор. После каждого обрыва проверяется, что загрузка успешна, значение старое или новое, все копии починены и повторная загрузка даёт то же самое.
- **Двойной сбой:** обрыв во время записи, а затем ещё и во время починки при следующем включении. Значение по-прежнему старое или новое.
- **20 000 случаев порчи** 1–2 копий из 3 случайными битами. Данные всегда восстанавливаются.
- **Порчу всех копий.** Все 3 копии кода испорчены → неисправность (а не `0000`). Все 3 копии состояния испорчены → блокировка.
- **Новый чип и чужие данные в EEPROM** → заводской код.
- **Износ ячеек за 5 лет.**

Итог: **51 440 проверок, 0 ошибок**.

### Запуск

Нужен компилятор C++: g++ или clang (на Windows — MinGW / MSYS2 / Git Bash с g++).

```
cd test
make
```

или без make:

```
sh test/run_test.sh
```

В конце должно быть: `checks: 51440, failures: 0`. Тест также запускается автоматически на GitHub при каждом изменении (см. `.github/workflows/ci.yml`).
